  `docs/plans/point7/2026-09-18-single-parse-indexing-pipeline.md`, commits 0abccdf..2270ff8).
  Finding: the HTML handler built a jsdom per selector rule (27 rules), so one index request parsed
  the page up to 56 times. Now exactly one: the HTML handler exports `parse`, the indexer builds a

  runs and its blobject is reused for ingest when the harmonizer did not change, endorsers get
  `document`. `packages/core/robots.js` was added and then deleted the same day; robots directives
  are now a `blobject.robots` field extracted by a non-overridable policy block and resolved in
  `resolveIndexPolicy` (`{ optedIn, harmonizer, refused }`).
- Policy semantics now: crawler-initiated requests (`active` mode, no `policyCheck`) are refused
  on any of robots `noindex`, `nofollow`, `none` ("Page forbids indexing (robots <token>).", HTTP
  403). Owner-initiated requests ignore robots entirely. `octo-policy: no-index` stays the OP
  opt-out and now also binds the crawler and feed-approved automatic opt-ins (previously ignored).
  Tests: `src/tests/indexPolicy.test.js`, `src/tests/indexPolicyIndexer.test.js`,
  `src/tests/htmlHandlerParse.test.js`, `src/tests/indexRouteErrorMapping.test.js`.
- New `profiles/bearblog/octothorpes.json` with `sources: ["client-endorsed"]`, selected via
  `OP_PROFILE` on the Bear deploy. `./octothorpes.json` untouched.
