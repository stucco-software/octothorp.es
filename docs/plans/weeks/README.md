# Weekly plans

One file per week, `YYYY-MM-DD-week.md`, dated to that week's Monday.

These are **to-do lists, not design docs**. They record only what was explicitly agreed in
conversation — no speculative scope, no invented tasks, no rationale that belongs in a design doc.
Where a task needs justification, link the doc that carries it rather than restating it here.

Rules of thumb:

- Every item is checkable and has a clear done-condition.
- Order is execution order. If two things can run in parallel, say so.
- If something slips, it moves to the next week's file with a one-line note — don't silently reopen.
- Link issues (`#285`) and plan docs by path. Keep the file short enough to read in a minute.
