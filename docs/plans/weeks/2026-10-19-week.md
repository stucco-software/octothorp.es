## Term identity mini epic ([#329](https://github.com/stucco-software/octothorp.es/issues/329), filed 2026-10-22)

Grouped the issues that all turn on one question — is a term's identity the percent-encoded URL or the string a human typed. Members: #285 (closed, the origin), #306 (read-side matching), #327 (fixed on this branch, the term lists), [#328](https://github.com/stucco-software/octothorp.es/issues/328) (new: drop legacy encoded-term bridging), #286 (the structural answer via `skos:prefLabel`). Label: `epic/term-identity`; #286 keeps its #316 membership, which still owns #195/#291/#315.

Sequencing ruled 2026-10-22: #328 first (subtractive, decides whether legacy spellings are supported at all), then #286, then retire both IRI-derivation sites. The non-ASCII half of #327 is deliberately left open — the code that would fix it is the code #328 deletes.

`src/tests/accessGate.test.js` carries the tripwire (`treats a percent-encoded non-ASCII name as the distinct term it is today`): it will fail when #328 or #286 lands, and that failure is the signal to move the term lists onto `prefLabel` rather than patch the test.
