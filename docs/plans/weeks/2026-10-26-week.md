## Testing guide: term identity (#329)

What changed, in one line each:

- #328: a term now has ONE spelling in queries; old percent-encoded non-ASCII term IRIs (e.g. `~/montr%C3%A9al` minted pre-#306) stop matching until their pages re-index. This is the accepted one-way door, not a bug.
- #286: every newly created term also gets `skos:prefLabel` with the verbatim human string; term pages and listings render the label instead of decoding the IRI slug.
- #329 step 3: term blocklist/allowlist and read matching compare the human string, so encoded spellings no longer evade `policies.access.blocks.terms`.

Reminder: `/index` returns before propagation finishes — wait for query quiescence before asserting reads.

### Local checklist (dev server + local Oxigraph, `.env` instance=localhost)

1. Backfill dry run — expect a list of term IRIs lacking prefLabel and NO writes:

       node scripts/backfill-term-labels.js

2. Backfill apply, then re-run dry run — expect an empty list (idempotent):

       node scripts/backfill-term-labels.js --write
       node scripts/backfill-term-labels.js

3. New-term emission: index any page carrying a fresh non-ASCII term (orchestra-pit works), then confirm the label exists:

       curl -s "$sparql_endpoint/query" --data-urlencode 'query=PREFIX skos: <http://www.w3.org/2004/02/skos/core#> SELECT ?s ?l WHERE { ?s skos:prefLabel ?l } LIMIT 20' -H 'Accept: application/sparql-results+json'

   Expect the verbatim string (e.g. `montréal`), not a percent-encoded form.

4. Term page renders the label: `/~/montréal` shows the human string as the heading, and a term WITHOUT a backfilled label still renders (decoded-slug fallback, no "undefined").

5. Blocklist both-spellings test: add `montréal` to `policies.access.blocks.terms` in profile.json, restart, index a page tagged `#montréal` and one tagged the encoded spelling — expect BOTH dropped at write time; remove the entry after.

6. Known regression to confirm, not fix: a legacy encoded term that existed before the merge returns 0 results under its decoded spelling (`everything/thorped?o=<decoded>`) until its source page is re-indexed; re-index one and confirm it comes back.

7. Unchanged behavior spot-checks:
   - `everything/thorped?o=demo` still returns results; exact match stays case-sensitive (`o=DEMO` -> 0).
   - `/~/demo` RSS still 200 with items (the #253 case-insensitive path).
   - `/vocabulary` still serves, with Term subClassOf skos:Concept present in the TTL.
