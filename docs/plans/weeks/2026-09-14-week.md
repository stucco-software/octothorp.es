## 0. Endorsement gate — the cutover-blocking slice

Bear's rule is a **marker** rule, which needs only the cheap half of the endorsement design. The
graph/web-of-trust half stays out of this week entirely and lands after cutover, safely, because
`sources: []` means it never executes for anyone who has not opted in.

### 0a. Schema (additive, defaults off)

- [ ] `policies.access.endorsement`: `sources` (ordered list), `depth`, `record`, `autoRegister`
- [ ] `sources` items accept **string shorthand or object form** (`{ "source": "graph", "depth": 2 }`)
      via `oneOf` — same array-or-path precedent as `blocks.domains`. Per-source `depth` retires the
      "depth is inert unless graph in sources" warning by construction
- [ ] `if`/`then` coupling: `autoRegister: true` **requires** `record: true` (schema error, not warning)
- [ ] `closed` becomes strictly whitelist-only — no registration, no endorsement. Update the
      `registration` enum description accordingly
- [ ] Coherence warnings per rev §6
- [ ] Defaults: `{ sources: [], depth: 1, record: false, autoRegister: false }` — stage OFF, so every
      existing profile behaves exactly as today

*Verify:* ajv accepts the four valid shapes and rejects `autoRegister` without `record` and
out-of-range `depth` (already prototyped — all six cases confirmed).

### 0b. Endorser loader

- [ ] Fixed location `static/endorsers/*.js`, walked at init, keyed by basename. **Not** profile-configured
- [ ] Contract: `export { name, endorse }`;
      `endorse({ origin, blobject, content, contentType, queryBoolean }) -> true | false | undefined`
- [ ] `content` (raw body) is passed as well as `blobject` — **required**: Bear's marker is a bare
      `<meta content='…'>` with no `name`, so no harmonizer selector extracts it and it is absent from
      the blobject
- [ ] Three-valued: `undefined` = no opinion, try next. `false` declines but does **not** deny — the
      stage is admit-only
- [ ] `graph` is reserved; a `static/endorsers/graph.js` is a **load-time error**, not warn-and-skip
      (shadowing the trust traversal is security-relevant in a way shadowing a harmonizer is not)
- [ ] Project discovered names as `api.endorsers.available` (projection only, never authored)

### 0c. Gate stage 4

- [ ] Insert endorsement between the registration check and the default deny in `checkAccessGate`
- [ ] Runs **only** when registration fails, and **only** under `registration: 'registered'`
- [ ] Sources tried in declared order, first admit wins
- [ ] Origin-level: an endorsement admits the site, not the page

### 0d. `bear-marker` endorser + Bear profile

- [ ] Module at `static/endorsers/bear-marker.js`; marker string from `.env`, never committed
- [ ] Port the robots veto: both `nofollow` **and** `noindex` → decline (`false`). Under admit-only
      semantics this yields the same outcome as `main`'s denial, with no special case
- [ ] Bear's `octothorpes.json` declares `sources: ["bear-marker"]`
- [ ] Closes merge audit **B5**

*Verify:* a Bear page with the marker indexes without being registered; without the marker it does not;

### 1a. Test profile-defined documentRecord projection

Regression-prone: the schema is threaded adapter → core as `documentRecordSchema`, and the CHANGELOG
records it was **already silently dropped once** for programmatic `get()`. Presence of the config is
not evidence the projection runs.

- [ ] HTTP path: `/get/…` returns the declared `documentRecord` predicates for a doc that carries them
- [ ] Programmatic path: `client.get()` / `op.get` returns the **same** projection for the same query
- [ ] Assert HTTP and programmatic outputs are identical — that equality is the actual regression guard
- [ ] Undeclared predicate on the page is **not** projected (the schema is an allowlist)
- [ ] Each declared `range` (`literal`, `uri`, `number`, `timestamp`) round-trips with the right type
- [ ] Namespaced predicates resolve via `vocabulary.namespaces`, not a hardcoded prefix

Touch points: `packages/core/api.js` (`documentRecordSchema` threading, ~lines 45/88),
`packages/core/blobject.js` (`getBlobjectFromResponse`, the projection loop ~line 110).

### 1b. Follow-up: extract built-in harmonizers to flat files

Immediate follow-up to approving the profile — **it may change profile structure**, so it wants to
land close behind rather than drift.

Today built-in harmonizers are inline JS objects in `packages/core/harmonizers.js` while site
harmonizers are JSON in `api.harmonizers.dir`. They do not share a signature, and
`harmonizerRegistry.register()` **warns and skips** on a name collision — so overriding a builtin is
not merely awkward, it is impossible.

- [ ] Decide the interpolation convention: the builtin `default` embeds the instance
      (`` `link[rel='preload'][href*='${instance}']` ``), so flat JSON needs either a token
      (`{{instance}}`) resolved at registry build, or instance-relative selectors that need no
      substitution
- [ ] Decide the override semantics: last-wins, or explicit (`"extends": "default"`)? Silent last-wins
      on a builtin name is a footgun
- [ ] **Open: does this need a new profile slot for default overrides?** Answer before the profile
      shape is treated as settled
- [ ] Extract builtins to flat files once both are decided

Related: #287 (a single harmonizer schema would then cover builtins and site harmonizers alike).

## 2. #285 — term IRI encoding, on both branches

The `~/` crash: a term containing a space produces an invalid SPARQL IRI → 500. Separate
implementations per branch; the call-site layouts differ, so this is not a cherry-pick.

- [ ] **`main`**: `termIri(instance, name)` helper, applied at ~28 sites across 11 files
      (`packages/core` *and* `src/lib` duplication, plus `src/lib/assert.js` and
      `src/routes/~/[thorpe]/{load.js,rss/+server.js}`)
- [ ] **`main`**: deploy and confirm against the reporting page on #279
- [ ] **`development`**: same helper, 18 sites across 4 files
      (`packages/core/{indexer,queryBuilders,api}.js`, `ld/rdfa2triples.js`)

Constraints, both branches:

- Encode once at IRI construction. **No decode/re-encode round-trip** — `decodeURIComponent` throws
  `URIError` on a term like `100%`.
- Read side matters as much as write side: `/get` params arrive URL-decoded, so a term written encoded
  but queried raw is unreachable.
- Encoding is **not** normalization. Leave `getFuzzyTags` alone.

Tests: `termIri()` unit coverage (space, `%`, `>`, `"`, `{`, `}`, non-ASCII, already-encoded input);
a regression indexing a doc whose harmonizer yields a spaced hashtag; a parity assertion that the
RDFa `<a href>` path and the harmonizer textContent path produce the **same** IRI.

This is intended as the **last hotfix to `main` before cutover**.
