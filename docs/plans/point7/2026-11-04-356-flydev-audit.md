## Dates

The fly.dev subjects have no `octo:created`/`octo:indexed`. The 1087 predicate-position triples carry the write timestamp. Earliest is 1757388259059 (2025-09-08), latest is 1792196560561 (2026-10-16), four days before the dump. Writes were still happening on v0.6 right up to cutover.

## Mechanism

These are not mis-minted terms. They are **relative link hrefs that Oxigraph resolved against its own endpoint URL**.

1. Sites mark links with `<a rel="octo:octothorpes" href="/tags/X.html">`. The default `link` harmonizer (`packages/core/harmonizers/default.json`) reads `element.href`. `parseHTML` in `packages/core/handlers/html/handler.js` builds a JSDOM document with no URL, so a relative href comes back unchanged (checked: `"/tags/X.html"`).
2. `indexer.js` pushes it to `handleMention` without checking that it is absolute. `mentionTriples` interpolates it as `<${o}>`.
3. Oxigraph resolves relative IRIs in an update against the request URL as base: `http://octothorpes.fly.dev/update`. So `</tags/X>` becomes `http://octothorpes.fly.dev/tags/X`. An empty `<>` becomes `/update` itself (63 occurrences). An undefined `o` becomes `/undefined` (19).
4. v0.6 `mentionTriples` (archive/v0.6, `packages/core/indexer.js`) also wrote `<${s}> <${o}> ${now}`. That is the source of the predicate-position triples.

## Verdict: live, not only legacy

- Steps 1-3 are unchanged on `development`. `mentionTriples` still writes `<${s}> ${p} <${o}>` and `<${o}> rdf:type`, and nothing guards against relative targets.
- The predicate-position timestamp triple is gone from current `mentionTriples`. That pattern is legacy (v0.6).
- Whether new rows still say `octothorpes.fly.dev` depends on the prod `sparql_endpoint` host. Whatever that host is, relative hrefs will now resolve to it.
- Instance config (`identity.instance`, `.env.example`, `profile.json`) was never `octothorpes.fly.dev` in the repo. The only code references are the webring `FILTER(!contains(str(?w), "octothorpes.fly.dev"))` in `packages/core/utils.js`, which excludes these junk rows.

## Recommended cleanup

1. Fix the write path first. In the HTML handler, resolve relative hrefs against the source page URL, either by passing `url` to JSDOM or with `new URL(value, source)`. As a second guard, have `handleMention` drop any target that `isURL` rejects. Add a test with a relative `rel="octo:octothorpes"` href. Also reject `undefined` and empty targets.
2. Migrate the existing data. Rewrite where the source page is known, delete where it isn't:
   - The edges are recoverable. `http://octothorpes.fly.dev/<path>` should be `<subject origin>/<path>`, because the hrefs were root-relative on the linking site. Rewrite the `octo:octothorpes` edges, the matching backlink `octo:url` blank nodes, and the reifier annotations.
   - Delete outright: the predicate-position timestamp triples (a v0.6 artifact that #270 no longer writes), the `/update` and `/undefined` rows, and the bare `rdf:type <octo:Page>` stubs on fly.dev subjects.
   - Sketch:
     ```sparql
     # 1. delete legacy predicate-position timestamps
     DELETE { ?s ?p ?t } WHERE { ?s ?p ?t . FILTER(STRSTARTS(STR(?p), "http://octothorpes.fly.dev/")) }
     # 2. rewrite edges to the linking site's origin
     DELETE { ?s octo:octothorpes ?bad }
     INSERT { ?s octo:octothorpes ?good . ?good rdf:type octo:Page }
     WHERE {
       ?s octo:octothorpes ?bad .
       FILTER(STRSTARTS(STR(?bad), "http://octothorpes.fly.dev/") && !STRENDS(STR(?bad), "/update") && !STRENDS(STR(?bad), "/undefined"))
       BIND(REPLACE(STR(?s), "^(https?://[^/]+).*$", "$1") AS ?origin)
       BIND(IRI(CONCAT(?origin, SUBSTR(STR(?bad), STRLEN("http://octothorpes.fly.dev")+1))) AS ?good)
     }
     # 3. same rewrite for backlink bnodes' octo:url (join through the bnode's source) and reifiers
     # 4. delete remaining fly.dev subjects/objects
     DELETE { ?x ?p ?o } WHERE { ?x ?p ?o . FILTER(STRSTARTS(STR(?x), "http://octothorpes.fly.dev/")) }
     DELETE { ?s ?p ?x } WHERE { ?s ?p ?x . FILTER(isIRI(?x) && STRSTARTS(STR(?x), "http://octothorpes.fly.dev/")) }
     ```
   - Run this together with the #270 reifier migration rehearsal on a dump, so the backlink and reifier shapes match post-migration. Re-indexing the five source sites after the write-path fix is an alternative to step 2. It is simpler, but it depends on the sites being reachable.
3. After cleanup, the webring `FILTER` workaround in `packages/core/utils.js` can be removed.
