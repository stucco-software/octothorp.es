Octothorpes badge builder

The badge is an image served by https://octothorp.es/badge. Requesting it tells the relay to index the page it appears on. Enter the URL of the page you are adding it to and copy the markup.

Build the markup




The URL is percent-encoded when it goes into ?uri=, which is why characters like &, ? and " are safe to paste — they come out as %26, %3F and %22 rather than breaking out of the attribute.

Or use the web component

If the page can load a script, <octo-badge> does the same job without a per-page URL. It reads the current page's address at runtime, so the same two lines work on every page of a site — no need to regenerate anything when you add a page.

<script type="module" src="https://octothorp.es/components/octo-badge.js"></script>
<octo-badge></octo-badge>

Attributes, all optional:

  • uri — index this URL instead of the current page. Use it when the badge sits somewhere that isn't the page you want indexed.
  • server — a different relay. Defaults to https://octothorp.es.
  • as — a harmonizer id or URL, if the page needs something other than the default reading.

The plain <img> above is the better choice when you can't run scripts, or when you want the markup to be legible and inert. The component is the better choice across a whole site.

What the three badges mean

The endpoint always answers with an image — never an error page — so the image you get back is the status.

Verified. The page's origin is registered with this relay, and indexing has been started. Indexing runs in the background after the image is sent, and its failures are only written to the relay's log — so this badge means the origin is verified, not that the page was successfully indexed. A page still needs the opt-in markup for indexing to complete.
Unregistered origin. The URL parsed, but its origin has not been verified with this relay. Register the domain and the badge changes on its own; nothing in the markup needs to change.
No usable URL. The relay could not get a valid URL from either ?uri= or the request's Referer header. Usually a malformed or missing uri, or a browser that stripped the referrer on a cross-origin image request — which is the reason to set ?uri= explicitly rather than relying on the referrer.
